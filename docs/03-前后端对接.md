# 前后端对接

本文说明前端调用后端、后端新增接口时需遵守的约定。本机运行见 [本地开发](01-本地开发.md)，代码结构见 [架构](02-架构.md)，核心功能的实现见 [业务说明](04-业务说明/)，服务器部署见 [部署](05-部署.md)。

## 1. 接口契约

前后端之间的接口以后端自动生成的 OpenAPI 文档为准，前端不另写接口类型。

- **后端生成**：springdoc 扫描 `cn.utcy.teaching` 下的控制器，后端运行时由 `http://localhost:8080/api/openapi` 提供 JSON，配置在 `backend/server/src/main/java/cn/utcy/teaching/shared/web/OpenApiConfiguration.java`。
- **前端保存**：`frontend/src/api/api-v1.json`，进入 Git。
- **前端生成调用代码**：`npm run generate:api` 由 orval 从 `api-v1.json` 生成 `frontend/src/api/generated/index.ts`。该文件不得手改，重新生成时会被覆盖。

页面通过 `frontend/src/api/client.ts` 导出的 `api` 调用接口，函数名即 OpenAPI 的 operationId，规则为「控制器名去掉 Controller + 方法名」，例如 `CourseMaterialController.createUploadTicket` 对应 `api.courseMaterialCreateUploadTicket(...)`。修改后端控制器的类名或方法名，前端函数名随之改变。

**修改接口的流程：**

1. 修改后端控制器或请求、响应的 record，重启后端。
2. 导出接口文档：

   ```bash
   curl --fail --silent --show-error http://localhost:8080/api/openapi --output frontend/src/api/api-v1.json
   ```

3. 在 `frontend/` 下执行 `npm run generate:api`，修改前端调用处，直至 `npm run typecheck` 通过。
4. `npm run check:api-client` 会重新生成一次，与 Git 中的 `generated/` 不一致时报错，用于发现遗漏的重新生成。

`check:api-client` 只比对 `api-v1.json` 与生成代码，无法发现后端已修改但未重新导出 `api-v1.json` 的情况，因此第 2 步不可省略。

**路径约定：** 所有接口以 `/api/v1` 开头。课程中的内容都挂在课程路径下，例如：

- `GET /api/v1/courses/{courseId}/materials`：资料库列表
- `PUT /api/v1/courses/{courseId}/coursewares/{coursewareId}/ops`：智能课堂编辑操作
- `POST /api/v1/courses/{courseId}/knowledge-bases/{kbId}/documents`：知识库入库
- `GET /api/v1/courses/{courseId}/knowledge-graph-builds/{buildId}`：知识图谱构建详情

不属于课程的接口有：`/api/v1/session`（登录会话）、`/api/v1/accounts`（账户管理）、`/api/v1/account/ai-config`（本人的 AI 服务密钥）、`/api/v1/platform`（平台设置）、`/api/v1/notifications/announcements`（平台公告）、`/api/v1/blockcoding`（积木编程助手对话）、`/api/v1/admin/judge`（判题运维）。

### 请求体和响应体的字段规则

请求体和响应体都用 Java record 定义。`shared/web/RecordOpenApiContractCustomizer.java` 把 record 的约束写入 OpenAPI，`shared/web/OpenApiSchemaContractTest.java` 校验这条规则。

- **请求 record 的每个字段都是必填的**，前端必须带上全部字段。
- 可为空的字段在 OpenAPI 中写作 `"type": ["integer", "null"]`，同时仍在 `required` 中。因此「可选」字段也必须传，值可以是 `null`。例如上传资料时的 `parentId`：放在根目录时传 `null`。
- 字段是否可为空的判定：基本类型（`int`、`long`、`boolean`）以及标注 `@NotNull` / `@NotBlank` / `@NotEmpty` 的字段不可为空；其他引用类型默认可为空；有 `@Schema` 注解时以其 `nullable` 为准。
- **响应 record 的每个字段都会出现**，只有标注 `@Schema(nullable = true)` 的字段值可能为 `null`。

后端反序列化是严格的（`application.yml` 的 `spring.jackson.deserialization`）：请求体含未知字段、缺少字段或 JSON 后有多余内容时，返回 400「请求内容格式不正确」。前端的请求体必须与接口文档完全一致。

## 2. 前端请求客户端

`frontend/src/api/client.ts` 中的 `http` 是项目的 axios 实例，生成的 `api` 基于它：

- **Cookie**：`withCredentials: true`，登录状态由 Cookie 保持，前端不保存任何登录令牌。
- **防伪令牌（CSRF）**：发送 POST、PUT、PATCH、DELETE 请求前，先调用 `GET /api/v1/session/csrf` 取得 `{ headerName, token }`，再把令牌放入对应请求头（后端规定头名为 `X-CSRF-TOKEN`）。令牌取得后缓存，登录、登出、修改密码和登录失效后清除并重新获取（见 `frontend/src/stores/session.ts`）。
- **超时**：未设置超时；耗时任务通过第 5 节的流式接口执行。
- **错误归一化**：后端返回的错误体转换为 `ApiProblem`，包含 `status`、`type`、`requestId`。无法连接服务时抛出「无法连接教学平台服务，请确认服务已经启动」；返回体不符合约定格式时抛出「服务返回的数据格式错误，请联系管理员」。
- **显示错误**：页面统一用 `errorMessage(error)` 取得提示文字。后端返回请求编号时，末尾自动附加「（错误编号 xxxxxxxx）」。
- **登录失效**：除登录接口和「查询当前用户」接口外，任何请求返回 401 时都会清除令牌、跳转登录页，并记录原页面地址（见 `frontend/src/features/auth/sessionExpiry.ts`）。

## 3. 登录与会话

会话接口在 `backend/server/src/main/java/cn/utcy/teaching/identity/api/SessionController.java`：

| 接口 | 作用 |
|---|---|
| `GET /api/v1/session/csrf` | 获取防伪令牌，无需登录 |
| `POST /api/v1/session/login` | 登录，请求体 `{ username, password }`，成功时返回当前账户 |
| `GET /api/v1/session` | 当前登录的账户，未登录返回 401 |
| `POST /api/v1/session/logout` | 登出，返回 204 |

- 会话 Cookie 名为 `TEACHING_SESSION`，带 `HttpOnly`、`SameSite=Strict`，是否仅限 HTTPS 由 `SESSION_COOKIE_SECURE` 控制。会话存于 Redis，有效期 8 小时。
- 登录失败次数超过限制时返回 429，阈值在 `application.yml` 的 `login-throttle`。
- 无需登录即可访问的只有：获取防伪令牌、登录、`GET /api/v1/platform/public`（站点名称等公开设置）、`GET /api/openapi`、健康检查。
- 每次请求都核对账户的最新状态。账户被停用、角色或密码被修改后，旧会话的下一次请求返回 401「账户状态、角色或凭据已变更，请重新登录」。
- root 使用初始密码登录后，除 `PUT /api/v1/accounts/me/password`、会话接口和公开设置外，其他请求返回 403「当前账户必须先修改初始密码」（`identity/infrastructure/InitialPasswordChangeFilter.java`）。

返回码的含义：

- **401**：未登录或登录已失效。
- **403**：已登录但无权执行该操作，统一提示「当前账户无权执行此操作」。业务代码主动拒绝时，用 `ForbiddenOperationException` 给出具体原因。
- 部分学生端接口不区分「不存在」和「无权查看」，统一返回 404。例如未发布的课件对学生返回「课件不存在」。

## 4. 错误格式

所有错误按 RFC 9457 的 Problem Details 返回，`Content-Type` 为 `application/problem+json`：

```json
{
  "type": "urn:teaching:problem:domain-error",
  "title": "资源不存在",
  "status": 404,
  "detail": "课件不存在",
  "instance": "/api/v1/courses/6/coursewares/10",
  "requestId": "3f9a1c2e"
}
```

- `detail` 是面向用户的中文提示，前端原样显示。
- `type` 只有四种：`domain-error`（业务错误）、`validation-error`（请求参数或格式错误）、`security-error`（登录与权限）、`internal-error`（未预期的服务端异常），前缀均为 `urn:teaching:problem:`。
- 参数校验失败时，`detail` 固定为「请求参数校验失败」，并附带 `errors` 对象，键为字段名，值为该字段的校验提示。

**后端抛错的方式：** 业务代码只抛出 `shared/error/` 下的异常，由 `shared/error/ApiExceptionHandler.java` 统一转换为上述格式。异常与状态码的对应：

| 异常 | 状态码 | `title` |
|---|---|---|
| `BadRequestException` | 400 | 业务处理失败 |
| `UnauthorizedException` | 401 | 需要登录 |
| `ForbiddenOperationException` | 403 | 无权执行此操作 |
| `NotFoundException` | 404 | 资源不存在 |
| `ConflictException` | 409 | 业务状态冲突 |

异常的 message 原样成为 `detail`，因此必须写成用户能据以操作的中文，不得出现字段名、表名、异常类名等技术细节，技术细节只写入日志。数据库唯一约束冲突统一返回 409「数据与现有记录冲突或仍被其他内容引用」。其他未捕获的异常返回 500「服务器处理请求时发生错误」，完整堆栈记入 ERROR 日志。

**请求编号：** `shared/web/RequestIdFilter.java` 为每个 HTTP 请求生成一个 8 位十六进制编号，写入该请求期间的每条日志、响应头 `X-Request-Id` 和错误响应体的 `requestId`。用户报告问题时提供界面上的「错误编号」，在日志中检索即可找到该请求的全部记录。后台任务线程（如流式接口中运行的生成任务）不在请求线程内，其日志不带编号。

## 5. 长任务的实时推送

AI 生成、语音合成、文档入库等耗时任务通过 SSE（`text/event-stream`）推送进度。后端的运行机制见 [长任务与实时推送](04-业务说明/02-长任务与实时推送.md)，本节只列接口约定。

### 事件格式

每个事件是一行 `data: {JSON}`，事件之间空一行。不使用 SSE 的 `event:` 字段，事件类型由 JSON 中的 `type` 区分。以下类型各接口通用：

- `{ "type": "error", "message": "..." }`：任务失败，流随即结束。
- `{ "type": "done", ... }`：任务完成，附结果摘要。
- `{ "type": "heartbeat" }`：智能问答和试题生成在模型长时间思考时每 5 秒发送一次，前端忽略。

接口在建立连接阶段被拒绝时（无权限、参数错误、未配置 AI 密钥等），返回第 4 节格式的普通错误响应。

### 两种流

**POST 流（请求即任务）：** 任务随请求运行，浏览器断开连接（前端用 `AbortController` 中止）后任务停止，已落库的结果保留。

| 功能 | 接口（均在 `/api/v1/courses/{courseId}` 下） | 事件 |
|---|---|---|
| 智能课堂：解析素材 | `POST /coursewares/{id}/materials`（multipart，字段 `files`） | `progress{message}`、`done{bundleId, chars, images, ...}` |
| 智能课堂：出大纲 | `POST /coursewares/{id}/outline` | `trace`、`outline{title, scenes, images}` |
| 智能课堂：按大纲生成 | `POST /coursewares/{id}/generate` | `trace`、`scene_start`、`scene_done`、`scene_failed`、`done{version, total, failed}` |
| 智能课堂：生成讲稿 | `POST /coursewares/{id}/speech`，请求体 `{ scope: "missing" \| "all" }` | 同上 |
| 智能课堂：单页重做 | `POST /coursewares/{id}/scenes/{sceneId}/regenerate` | `scene_start`、`trace`、`scene_done`、`done` |
| 智能课堂：合成语音 | `POST /coursewares/{id}/tts` | `progress{done, total}`、`done{version, generated, skipped}` |
| 智能课堂：学生随堂提问 | `POST /coursewares/{id}/questions` | `answer_delta{text}`、`retry`、`done{answer}` |
| 试题生成 | `POST /questions/generate` | `stage`、`progress`、`explore_text`、`tool`、`notice`、`plan`、`question{index, total, draft}`、`heartbeat`、`done{total}` |
| 智能问答 | `POST /tutor/sessions/{sessionId}/messages` | `user_message`、`seed_sources`、`round`、`thinking`、`content`、`tool`、`notice`、`heartbeat`、`done`、`title` |

积木编程助手的接口不在课程路径下：`POST /api/v1/blockcoding/chat-sessions/{sessionId}/messages`，事件有 `content`、`reply_reset`、`narration`、`round`、`tool`、`notice`、`script`、`question`、`browser_tool`、`done{messageId, seq}`。其中 `browser_tool` 要求前端在积木编辑器中执行一项操作，前端执行完毕后将结果 POST 到 `/api/v1/blockcoding/chat-sessions/{sessionId}/browser-tool-results`，请求体 `{ callId, ok, result, error }`，助手随后继续。

**GET 流（后台任务）：** 任务由普通 POST 接口启动，在后台独立运行，关闭页面或断网不影响任务。浏览器随时可用 GET 接入进度流：先补发已发生的事件，再接收新事件。任务已结束时只收到一条 `status` 事件（当前持久化的状态），流随即结束。停止任务须调用取消接口，断开连接不会停止任务。

| 功能 | 启动 | 进度流 | 取消 |
|---|---|---|---|
| 知识库：文档入库 | `POST /knowledge-bases/{kbId}/documents` | `GET /knowledge-bases/{kbId}/documents/{documentId}/events` | `POST .../documents/{documentId}/cancel` |
| 知识库：重建索引 | `POST /knowledge-bases/{kbId}/rebuild` | `GET /knowledge-bases/{kbId}/rebuild/events` | `POST /knowledge-bases/{kbId}/rebuild/cancel` |
| 知识图谱构建 | `POST /knowledge-graph-builds` 及后续各步 | `GET /knowledge-graph-builds/{buildId}/events` | `POST /knowledge-graph-builds/{buildId}/cancel` |

知识库入库的事件有 `stage`、`parse_progress`、`embedding_progress`、`document_start`、`done`、`status`。知识图谱构建的事件有 `stage`、`parse_progress`、`toc_ready`、`progress`、`extracted`、`status`，没有 `done`，以 `status` 表示当前阶段。

### 前端读取

流式接口通过 `frontend/src/api/sse.ts`（`fetch` 加流式读取）调用：

- `streamPost(url, body, onEvent, signal)`：JSON 请求体的 POST 流，自动附带防伪令牌。
- `streamPostMultipart(url, form, onEvent, signal)`：上传文件并接收进度。
- `streamGet(url, onEvent, signal)`：接入后台任务的进度流，无需防伪令牌。
- 建立连接阶段被拒绝时抛出 `SseHttpError`，带状态码，调用方据此决定重试或报错。

每个功能目录下的 `*Stream.ts` 定义该功能的事件类型和接口地址：`features/courseware/coursewareStream.ts`、`features/courses/questionStream.ts`、`features/tutor/tutorStream.ts`、`features/knowledgebase/knowledgebaseStream.ts`、`features/knowledgegraph/kgBuildStream.ts`、`features/blockcoding/chatStream.ts`。事件类型不在 OpenAPI 中，由前后端各自手写，**后端修改事件名或字段时，必须同步修改对应的 `*Stream.ts`**。

## 6. 文件上传和下载

### 资料库文件：浏览器直传 OSS

文件不经过后端，由浏览器直接上传到阿里云 OSS，流程在 `frontend/src/features/courses/materialUpload.ts`：

1. 浏览器计算文件的 SHA-256。
2. **申请上传票据**：`POST /api/v1/courses/{courseId}/materials/upload-tickets`，请求体 `{ parentId, name, contentType, sizeBytes, sha256 }`。后端检查权限和同目录重名，建立「待上传」的资料记录，返回 `{ materialId, url, expiresAt, method: "PUT", requiredHeaders }`，签名地址 10 分钟内有效。
3. **上传**：浏览器以 `PUT` 将文件发往 `url`，必须原样附带 `requiredHeaders` 中的三个请求头：`Content-Type`、`x-oss-meta-sha256`、`x-oss-forbid-overwrite`。
4. **确认上传**：`POST /api/v1/courses/{courseId}/materials/{materialId}/upload-confirmation`。后端到 OSS 核对文件大小和 SHA-256，一致后才将资料置为可用。

超过 24 小时未确认的待上传记录由后台自动清理。同目录重名时申请票据返回 409，前端自动改名为「名称 (2)」后重试，最多 5 次。

知识库入库和试题生成的附件，都先按上述流程上传到资料库，再把 `materialId` 交给对应接口。

浏览器直传依赖 OSS bucket 的跨域规则，配置见 [本地开发](01-本地开发.md) 第 3 步。

### 下载

下载同样不经过后端：

- **资料库文件**：`POST /api/v1/courses/{courseId}/materials/{materialId}/download-tickets`（学习端）或 `.../management/download-tickets`（课程管理端），返回 `{ url, expiresAt }`，签名地址 10 分钟内有效。
- **智能课堂的图片、视频、讲稿音频**：后端在课件数据中给出签名地址，2 小时内有效。

### 经过后端的上传

以下上传以 multipart 表单发往后端，由后端处理后存入 OSS，单个文件上限 256 MB：

- 智能课堂：上传素材 `POST /coursewares/{id}/materials`（字段 `files`，最多 5 个，返回进度流）、插入图片 `POST /coursewares/{id}/images`、上传视频 `POST /coursewares/{id}/videos`（字段 `file`）。
- 编程题：导入题目包 `POST /programming-problems/package-imports`（字段 `file`）。

以上路径均在 `/api/v1/courses/{courseId}` 下。

## 7. 通用约定

- **ID**：数据库主键是 64 位整数，JSON 中为数字。智能课堂的页面编号、内容块编号是字符串（如 `scene-3`、`blk-paragraph-1`），在课件内唯一。
- **时间**：多数接口的时间是 ISO 8601 格式的 UTC 字符串（如 `2026-10-01T12:30:00Z`），前端用 `shared/format.ts` 的 `formatDateTime` 显示。**智能课堂相关接口例外**，时间是毫秒时间戳，用 `formatEpochMillis` 显示。新接口使用 ISO 字符串。
- **分页**：分页列表（账户、课程、公告、积木作品、智能问答会话）使用查询参数 `page`（从 1 开始）和 `size`（默认 20，最大 100），返回 `{ items, page, size, total, totalPages }`（`shared/web/PageResponse.java`）。其余列表返回数组。
- **枚举**：JSON 中传递的枚举取值以 OpenAPI 文档为准。多数为小写加下划线（如试题类型 `single_choice`、角色 `teacher`），也有大写（如判题结果 `WRONG_ANSWER`、出题方式 `MIMIC`）和中文（知识点类型 `概念`）。查询参数中的枚举由各模块的 `*EnumConversionConfiguration` 严格转换，取值无法识别时返回 400。
- **批量删除**：使用 `POST .../deletions`，请求体 `{ ids: [...] }`，例如资料库的 `POST /api/v1/courses/{courseId}/materials/deletions`。

## 8. 端到端测试中的接口打桩

前端端到端测试（`frontend/tests/e2e/`）不连接真实后端：

- `playwright.config.ts` 把开发服务器开在 8068 端口，并设置 `API_PROXY_TARGET=http://127.0.0.1:9`。`/api` 被代理到一个没有服务的端口，未打桩的请求都会失败。
- 每个用例用 Playwright 的 `page.route(...)` 拦截所需接口，以 `route.fulfill(...)` 返回测试数据。登录状态通过拦截 `GET /api/v1/session` 和 `GET /api/v1/session/csrf` 模拟，示例见 `courseware-workbench.spec.ts`。
- `fixture.ts` 为所有用例统一拦截 `GET /api/v1/platform/public`，用例从此处导入 `test` 和 `expect`。
- 打桩的返回体须与 OpenAPI 文档的结构一致，接口修改后需同步修改对应用例中的测试数据。
