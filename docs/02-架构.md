# 架构

本文说明代码的组织方式、各部分的职责，以及新功能应写在哪里。本机运行见 [本地开发](01-本地开发.md)，核心功能的实现见 [业务说明](04-业务说明/)，HTTP 约定见 [前后端对接](03-前后端对接.md)，服务器部署见 [部署](05-部署.md)。

## 仓库目录

| 目录 | 内容 |
|---|---|
| `backend/` | Maven 多模块工程，父 pom 和 Maven Wrapper（`mvnw`）在这一层 |
| `backend/server/` | 业务后端：Spring Boot 模块化单体，包含全部接口、业务规则和数据库访问 |
| `backend/judge-contract/` | 业务后端和判题进程共用的「测试数据包」格式：读写、校验、SHA-256 |
| `backend/judge-worker/` | 判题进程：独立的 Spring Boot 程序，从 Redis 领取判题任务，在沙箱中编译运行学生代码 |
| `frontend/` | 前端：Vue 3 + TypeScript，面向桌面浏览器 |
| `scratch-editor/` | 积木编程使用的编辑器，官方 scratch-gui 的改制版，改动范围见 `scratch-editor/README.md` |
| `deploy/` | Docker 相关的全部文件：`compose.yaml` 编排、`compose.dev.yaml` 本机开发叠加、`docker/<服务>/` 各服务的 Dockerfile、中间件启动脚本、`secrets/` 密码文件 |
| `docs/` | 项目文档 |
| `logs/` | 运行时写出的日志文件，不进入 Git |

## 后端

### 技术栈

JDK 21、Spring Boot 3.5、Spring Modulith 1.4、MyBatis-Plus 3.5（数据访问）、MySQL 8.4、Spring Security + Spring Session（会话存于 Redis）、springdoc（生成接口文档）、LangChain4j 1.19（调用大模型）。版本以 `backend/pom.xml` 和 `backend/server/pom.xml` 为准。

### 模块

`backend/server/src/main/java/cn/utcy/teaching/` 下每个子包是一个业务模块，根包只放启动类 `TeachingApplication`。模块的中文名和依赖声明写在各自的 `package-info.java` 中。

| 包 | 名称 | 职责 | 可依赖 |
|---|---|---|---|
| `ai` | AI 模型接入 | 调用大模型、向量化、语音合成、文生图；PDF 和 Office 文档解析；用户填写的 AI 密钥加密保存 | `shared` |
| `identity` | 账户与权限 | 账户、登录会话、密码规则、登录失败限流、启动时创建 root 账户、Spring Security 配置 | 未声明（目前只引用 `shared`） |
| `platform` | 平台设置 | 站点名称、页脚文字 | 未声明（目前只引用 `shared`） |
| `course` | 课程 | 课程、成员与课程码、课程内容（单元和条目）、课程访问校验、删除课程时调用各模块善后 | `shared`、`identity::application`、`ai::application` |
| `resource` | 资料库 | 课程文件（浏览器直传 OSS）、OSS 客户端配置、OSS 对象删除队列 | `shared`、`course::application` |
| `question` | 试题 | 试题和作答；资源生成中的试题生成 | `shared`、`course`、`identity`、`knowledgebase`、`retrieval`、`resource` 的 `application`，`ai::agent`、`ai::document`、`ai::llm`、`ai::structured` |
| `programming` | 编程题 | 编程题、测试数据包、题目包导入、提交、判题任务发布与结果回收、重判 | `shared`、`course::application`、`identity::application`、`judgecontract` |
| `knowledgebase` | 知识库 | 知识库和文档、入库（解析 → 分块 → 向量化 → 写入 Elasticsearch）、检索 | `shared`、`course::application`、`resource::application`、`ai::document`、`ai::llm` |
| `retrieval` | 知识库检索 | 智能问答和试题生成共用的知识库检索工具 | `shared`、`knowledgebase::application`、`ai` |
| `knowledgegraph` | 知识图谱 | 图谱的节点和关系、节点挂载资料、由教材自动构建图谱 | `shared`、`course::application`、`resource::application`、`ai::document`、`ai::llm`、`ai::structured` |
| `courseware` | 智能课堂 | 课件的大纲、逐页生成、讲稿、编辑、语音合成、播放、学习记录、随堂问答 | `shared`、`course::application`、`identity::application`、`ai::document`、`ai::llm`、`ai::media`、`ai::structured` |
| `tutor` | 智能问答 | 课程的问答助手配置、学生的对话会话 | `shared`、`course`、`knowledgebase`、`retrieval`、`identity` 的 `application`，`ai::agent`、`ai::llm` |
| `analytics` | 学情 | 学生学习事件记录、按课程统计学情、导出 Excel | `shared`、`course::application`、`identity::application`、`knowledgegraph::application`、`knowledgegraph::vocabulary` |
| `blockcoding` | 积木编程 | 课程的积木编程开关和辅导提示词、积木作品、积木编程助手对话 | `shared`、`course::application`、`ai::agent`、`ai::llm` |
| `notification` | 公告 | 平台公告和课程公告 | `shared`、`course::application` |
| `shared` | 共享内核 | 各模块共用的基础类型，见下文 | 无 |

`模块::接口` 表示只能使用该模块对外开放的那一部分：

- 业务模块对外开放的都是 `application` 子包；
- `ai` 按用途分为 `llm`、`agent`、`structured`、`document`、`media`、`application` 六个开放接口；
- `knowledgegraph::vocabulary` 是图谱的节点类型、关系类型、知识点类型三个枚举。

`judgecontract` 是 `backend/judge-contract` 中的包。

模块之间只能按声明的依赖调用，`backend/server/src/test/java/cn/utcy/teaching/ApplicationModulesTest.java` 检查整个工程，越界引用会导致测试失败。

### 模块内分层

每个业务模块按四层组织：

| 子包 | 内容 |
|---|---|
| `api` | Controller 和请求体（Java record），参数校验和转发 |
| `application` | 用例服务：权限和归属校验、事务、调用领域对象和基础设施；同时是对其他模块开放的入口 |
| `domain` | 实体、枚举和纯业务规则（不依赖 Spring 和数据库的部分） |
| `infrastructure` | MyBatis-Plus 的 Mapper、配置类和 `*Properties`、外部服务客户端、各模块对共享接口的实现 |

`blockcoding` 另有 `engine` 子包，是把积木文本编译为编辑器积木的编译引擎。

### 共享内核

`shared` 是开放模块，其子包可被任何模块直接使用：

| 子包 | 内容 |
|---|---|
| `actor` | 当前登录者（`CurrentActor`、`Actor`）、四种系统角色（`SystemRole`）、教学内容归属校验（`OwnershipPolicy`） |
| `error` | 业务异常（`BadRequestException`、`NotFoundException`、`ConflictException` 等）和统一的错误响应（`ApiExceptionHandler`） |
| `web` | 分页响应、请求编号过滤器（`RequestIdFilter`）、OpenAPI 配置 |
| `storage` | 对象存储的共用接口：删除队列、完整性校验、启动时检查 bucket |
| `course` | 供各模块接入课程级流程的接口：删除课程时的善后（`CourseDeletionGuard`）、课程内容条目的来源（`CourseOutlineSourceProvider`）、内容是否被引用（`CourseContentReferenceSource`）等 |
| `learning` | 学习事件的类型和记录接口，由 `analytics` 实现 |
| `run` | 后台长任务的写围栏和心跳（`RunFence`）、判滞巡检骨架（`StaleRunCleaner`） |
| `sse` | 服务端推送：进度总线（`ProgressBus`）、心跳、推送使用的线程池 |
| `util` | 有界并行、文本截断等工具 |
| `config` | 时钟（统一 UTC）、MyBatis 配置、本机开发时定位仓库根目录 |

`shared/course` 和 `shared/learning` 中的接口由各模块分别实现，课程模块删除课程、组装课程内容时因此不必依赖其他模块：

- 每个模块提供自己的 `CourseDeletionGuard`，课程模块删除课程时依次调用；
- 学生在各模块中的学习行为，通过 `LearningEventRecorder` 记入学情。

### 判题进程

判题进程是独立的程序，代码在 `backend/judge-worker/`，包结构如下：

| 子包 | 内容 |
|---|---|
| `worker` | 从 Redis Stream 读取任务、发布结果、健康检查 |
| `sandbox` | 调用镜像内置的 go-judge 沙箱编译运行 |
| `packagefile` | 从 OSS 下载测试数据包并在本地缓存 |
| `model` | 任务和结果的数据结构 |
| `config` | 配置和 OSS 凭据读取 |

支持 C17、C++20、Python 3.12。编译器（gcc-13、g++-13、python3.12）和 go-judge 都安装在镜像中（`deploy/docker/judge-worker/Dockerfile`）。判题的完整流程与超时对账见 [编程题判题](04-业务说明/04-编程题判题.md)。

## 数据库

表结构定义在 `schema.sql` 中。MySQL 首次初始化数据目录时执行它，已有数据库不会自动更新，修改表结构需在库上手工执行对应的 `ALTER`。

以下规则不易从代码中直接看出：

- **不使用外键。** 全库没有 `FOREIGN KEY`。删除父数据时由代码显式删除或拒绝子数据（删除课程经由各模块的 `CourseDeletionGuard`）；插入子数据前先读取父数据确认其存在。
- **时间统一为 UTC。** 数据库连接、MySQL 服务、后端时钟（`shared/config/ClockConfiguration`）均为 UTC，前端显示时转换为本地时间。
- **OSS 对象不在事务中删除。** 业务事务只向 `object_deletion_job` 表写入删除任务，提交后由 `resource` 模块的删除队列删除 OSS 对象，数据库回滚时文件不会被误删。
- **上传分两步。** 先建立「待上传」记录并签发直传地址，浏览器上传完成后再确认；超时未确认的记录由 `PendingUploadJanitor` 清理。

## AI 部分

所有 AI 调用都经过 `ai` 模块，业务模块不直接接触大模型的 HTTP 接口或 SDK。各模块维护自己的提示词（`resources/<模块>/prompts/`）和模型参数（`application.yml` 的 `teaching.<模块>`）。调用入口、结构化输出、智能体和提示词写法见 [大模型基础组件](04-业务说明/01-大模型基础组件.md)，密钥的归属见 [课程与权限](04-业务说明/03-课程与权限.md)。

耗时任务有两种运行方式：

- **跟随连接**：任务在浏览器发起的流式请求中运行，连接断开即停止，已落库的结果保留。适用于智能课堂的生成与语音合成、试题生成、智能问答、积木编程助手。
- **后台运行**：任务独立于连接，浏览器可随时接入查看进度；任务停滞或进程重启后由巡检判为失败，可重试。适用于知识库入库与重建、知识图谱构建。

具体机制见 [长任务与实时推送](04-业务说明/02-长任务与实时推送.md)。

## 新增功能

以「在课程中新增一类内容」为例，依次涉及以下位置：

1. **确定归属。** 按「这是哪个模块的能力」放入已有模块，确属独立的业务才新建模块。新建模块时在 `cn.utcy.teaching` 下建包并编写 `package-info.java`，声明中文名和依赖（只声明实际使用的开放接口）。
2. **表结构。** 在 `schema.sql` 中加表，同时在本机已有的库上手工执行对应的 `CREATE` / `ALTER`，不加外键。
3. **后端分层：**
   - `domain`：实体（`@TableName`）和规则；
   - `infrastructure`：Mapper；
   - `application`：服务；
   - `api`：Controller 和请求体。

   权限在 `application` 中校验，方法见 [课程与权限](04-业务说明/03-课程与权限.md)。出错时抛出 `shared/error` 中的异常，提示使用面向用户的中文。
4. **接入课程级流程。** 内容随课程删除的，实现 `CourseDeletionGuard`；可编排进课程内容的，实现 `CourseOutlineSourceProvider` 和 `CourseContentReferenceSource`；学生行为需计入学情的，调用 `LearningEventRecorder`。使用其他模块的能力时，在 `package-info.java` 中声明对其 `application` 的依赖。
5. **后端测试。** 在 `backend/server/src/test/java` 的同名包下添加测试，执行 `./mvnw clean verify`，其中 `ApplicationModulesTest` 检查模块依赖。
6. **更新接口代码。** 导出接口文档并重新生成前端接口代码，命令见 [本地开发](01-本地开发.md#提交前的检查)。
7. **前端。**
   - 在对应的 `src/features/<功能>/` 下编写组件，调用 `@/api/generated` 中生成的函数；
   - 课程内的管理功能加入 `AdminCourseDetailView.vue` 的页签，学生端加入 `CourseDetailView.vue`；
   - 独立页面在 `src/app/router/index.ts` 中添加路由。
8. **前端测试。** 在 `tests/unit/<功能>/` 添加单元测试，主要流程在 `tests/e2e/` 添加端到端测试，并执行 [本地开发](01-本地开发.md#提交前的检查) 中的前端检查命令。
