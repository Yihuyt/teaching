# 本地开发

本文说明如何在本机运行项目进行开发。MySQL、Redis、Elasticsearch、判题进程和积木编辑器运行在 Docker 中，后端和前端在本机运行，修改代码后无需重新构建镜像。代码结构见 [架构](02-架构.md)，服务器部署见 [部署](05-部署.md)。

以下命令均在仓库根目录执行，另有说明的除外。

## 环境要求

- JDK 21。`backend/.sdkmanrc` 指定了 `21.0.12-amzn`，使用 SDKMAN 时可在 `backend/` 下执行 `sdk env install` 安装。
- Node.js 24.11 或更高版本。
- Docker 及 Compose 插件（`docker compose` 命令）。
- 阿里云 OSS：一个私有 bucket（课程资料和判题测试数据以不同目录前缀存放，也可以分成两个），以及一个对它有读写权限的 AccessKey。

## 1. 准备密码和密钥

这些文件位于 `deploy/secrets/`，不进入 Git，各文件的用途见 `deploy/secrets/README.md`。

```bash
cd deploy/secrets
for name in mysql-root-password mysql-app-password redis-password elastic-password root-initial-password; do
  openssl rand -base64 36 | tr -d '\n' > "$name"; chmod 600 "$name"
done
openssl rand -base64 32 | tr -d '\n' > ai-config-key; chmod 600 ai-config-key
```

另建 `aliyun-oss-credentials`，写入 OSS 的 AccessKey，固定两行且顺序不可调换，并将权限设为 `600`：

```text
ALIYUN_OSS_ACCESS_KEY_ID=AccessKey ID
ALIYUN_OSS_ACCESS_KEY_SECRET=AccessKey Secret
```

MySQL 和 Elasticsearch 的密码在首次启动时写入各自的数据目录，此后修改这些文件不会改变已有数据的密码。

## 2. 填写 deploy/.env

```bash
cp deploy/.env.example deploy/.env
```

填写 `ALIYUN_OSS_ENDPOINT`（OSS 地域节点）、`ALIYUN_OSS_RESOURCE_BUCKET`（课程资料 bucket）和 `ALIYUN_OSS_TESTCASE_BUCKET`（判题测试数据 bucket，可以与前者相同）。Docker 中的服务和本机运行的后端都读取这个文件。

## 3. 配置 OSS 跨域规则

浏览器上传文件时直接传往后端签发的 OSS 地址，因此 bucket 需要在阿里云控制台配置跨域（CORS）规则（用了两个 bucket 时两个都要配）：

- 来源：`http://localhost:8067`，不使用 `*`
- 允许方法：`PUT`、`GET`、`HEAD`
- 允许请求头：`Content-Type`、`x-oss-meta-sha256`、`x-oss-forbid-overwrite`
- 暴露响应头：`ETag`、`x-oss-request-id`

bucket 保持私有，跨域规则不改变读写权限。

## 4. 启动 Docker 中的服务

```bash
docker compose -p teaching-platform --env-file deploy/.env -f deploy/compose.yaml -f deploy/compose.dev.yaml \
  up -d mysql redis elasticsearch scratch-editor judge-worker
```

首次执行时会构建判题进程和积木编辑器的镜像。`docker ps` 中五个容器均为 `healthy` 即启动完成。

| 服务 | 本机地址 |
|---|---|
| MySQL | `127.0.0.1:3306` |
| Redis | `127.0.0.1:6379` |
| Elasticsearch | `127.0.0.1:9200` |
| 积木编辑器 | `127.0.0.1:8069` |
| 判题进程 | 不开放端口，从 Redis 领取判题任务 |

MySQL 首次启动时执行 `backend/server/src/main/resources/db/schema.sql` 建表。此后修改 `schema.sql` 不会自动作用于已有数据库，需要在库上手工执行对应的 `ALTER`。

## 5. 启动后端

**IntelliJ IDEA：** 打开 `backend` 目录（不是仓库根目录），待 Maven 导入完成后运行 `server` 模块中的 `TeachingApplication`。无需设置环境变量或工作目录，后端会自行定位 `deploy/secrets/` 和 `deploy/.env`。

**命令行：**

```bash
cd backend
./mvnw --projects judge-contract --also-make install -DskipTests
./mvnw --projects server spring-boot:run
```

第一条命令仅在首次启动和修改 `judge-contract` 之后需要执行。

后端监听 `8080` 端口，访问 `http://localhost:8080/api/openapi` 返回 JSON 即表示启动成功。

## 6. 启动前端

```bash
cd frontend
npm install
npm run dev
```

访问 `http://localhost:8067/`。开发服务器将 `/api` 转发到 `8080` 端口的后端，将 `/scratch` 转发到 `8069` 端口的积木编辑器。

## 7. 首次登录

用户名 `root`，密码为 `deploy/secrets/root-initial-password` 的内容，首次登录后必须修改密码。

使用 AI 功能前，课程负责人需要在「账户设置 → AI 服务」中填写大模型 API Key 和 MinerU 令牌，规则见 [课程与权限](04-业务说明/03-课程与权限.md)。

## 停止服务

```bash
docker compose -p teaching-platform --env-file deploy/.env -f deploy/compose.yaml -f deploy/compose.dev.yaml stop
```

`stop` 和 `down` 都保留数据；`down -v` 会同时删除数据卷。

## 日志

后端日志输出在 IDEA 运行窗口或命令行。判题进程的日志用 `docker logs teaching-platform-judge-worker-1` 查看，文件日志在 `logs/judge-worker/`。按页面上的错误编号检索日志的方法见 [前后端对接](03-前后端对接.md)。

## 常见问题

- **端口被占用：** 3306、6379、9200、8069、8080、8067 中任一端口被其他程序占用时，对应服务无法启动。
- **后端启动时报告读不到密码：** 检查 `deploy/secrets/` 下的文件名是否与第 1 步一致。
- **启动日志中有 OSS 的 `AccessDenied` 错误：** AccessKey 对 bucket 没有权限，或 OSS 服务因欠费被释放。此时上传和下载都会失败，但启动检查不会拦住它（`doesBucketExist` 只在 bucket 不存在时报错）。到阿里云控制台核对 OSS 是否开通、bucket 是否存在、RAM 用户是否有该 bucket 的权限。
- **上传文件失败：** 检查第 3 步的跨域规则。

## 提交前的检查

后端：

```bash
cd backend
./mvnw clean verify
```

前端，在 `frontend/` 下：

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run install:e2e   # 仅首次需要,下载端到端测试使用的浏览器
npm run test:e2e
```

后端接口有变化时，启动后端，导出接口文档并重新生成前端接口代码：

```bash
curl --fail --silent --show-error http://localhost:8080/api/openapi --output frontend/src/api/api-v1.json
cd frontend && npm run generate:api
```

### 后端测试中的 AI 调用

单元测试不连接真实模型，使用 `backend/server/src/test/java/cn/utcy/teaching/ai/llm/` 下的两个替身：

- `ScriptedStreamingChatModel`：按脚本依次返回思考、正文和工具调用的假模型；
- `FakeLlm`：继承 `LlmCalls`，带工具的循环通过它驱动上面的假模型，单次文本调用按预设答案返回并记录收到的消息。

连接真实服务的测试只在设置对应环境变量时运行，环境变量指向仓库外的密钥文件：

| 测试 | 环境变量 |
|---|---|
| `LlmCallsLiveTest`（大模型） | `AI_LIVE_KEY_FILE` |
| `MineruLiveSmokeTest`（MinerU） | `MINERU_LIVE_TOKEN_FILE` |
| `ScratchGenerationEvalTest`（积木编程生成评测） | `BLOCKCODING_LIVE_KEY_FILE` |
