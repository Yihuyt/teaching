# 课程与权限

系统中的教学内容都归属课程：资料、试题、编程题、知识图谱、知识库、智能问答助手、智能课堂课件、积木作品、课程公告。本文说明一个请求怎样确定「谁在操作、能不能做」。

代码在 `backend/server/src/main/java/cn/utcy/teaching/` 下：登录与会话在 `identity`，当前登录者与角色在 `shared/actor`，课程的访问校验在 `course`。下文省略这一前缀。模块划分见 [架构](../02-架构.md)。

## 整体流程

```text
浏览器请求（带会话 Cookie）
  → Spring Security 从 Redis 会话恢复登录者
  → AccountSessionValidationFilter：与数据库中的账户状态核对，不一致则会话失效，返回 401
  → Controller → 模块的应用服务
        ├ CurrentActor.require()                     取得当前登录者（编号、用户名、系统角色）
        ├ CourseAccess.requireLearningAccess(...)    学习：课程已发布，且是课程成员
        └ CourseAccess.requireManagementAccess(...)  管理：root、admin 可管理所有课程，teacher 管理自己负责的课程
```

权限校验写在后端应用服务中，URL 层只区分「无需登录」和「需要登录」。

## 主流程

### 1. 当前登录者

登录后，Spring Security 把账户快照存入 Redis 中的会话。业务代码通过 `shared/actor/CurrentActor` 取得 `Actor`（账户编号、用户名、系统角色），未登录时返回 401。

会话中的快照在登录时生成。`identity/infrastructure/AccountSessionValidationFilter` 在每个请求上把快照与数据库中的账户比对，账户被停用、角色或密码被修改后，旧会话在下一次请求时失效。

### 2. 系统角色

系统角色有 root、admin、teacher、student 四种（`shared/actor/SystemRole`）。能否管理某项有负责人的内容，由 `shared/actor/OwnershipPolicy` 判断：

```java
// backend/server/src/main/java/cn/utcy/teaching/shared/actor/OwnershipPolicy.java
public boolean isContentManager(Actor actor, long ownerId) {
    return actor.role().canManageTeachingContent()
            && (actor.role() != SystemRole.TEACHER || actor.userId() == ownerId);
}
```

root、admin 可管理所有内容，teacher 管理自己负责的内容，student 不能管理内容。

### 3. 课程的学习权与管理权

其他模块通过 `course/application/CourseAccess` 校验课程权限，实现类是 `CourseApplicationService`。管理权以课程负责人为准，交给 `OwnershipPolicy` 判断；学习权与系统角色无关，只看课程是否发布、操作者是否为成员：

```java
// backend/server/src/main/java/cn/utcy/teaching/course/application/CourseApplicationService.java
public void requireLearningAccess(long courseId, Actor actor) {
    Course course = requireCourse(courseId);
    if (!course.isPublished()) {
        throw new ForbiddenOperationException("课程尚未发布");
    }
    if (!members.exists(new LambdaQueryWrapper<CourseMember>()
            .eq(CourseMember::getCourseId, courseId)
            .eq(CourseMember::getAccountId, actor.userId()))) {
        throw new ForbiddenOperationException("无权访问该课程");
    }
}
```

因此教师或管理员要在学习端查看课程，同样需要用课程码加入。管理端与学习端是两套接口：学习端接口校验学习权，管理端接口校验管理权，分别由前端 `features/courses/views/CourseDetailView.vue` 和 `AdminCourseDetailView.vue` 调用。前端路由的角色限制只决定页面能否进入，接口的权限以后端校验为准。

成员由学生用课程码自行加入，课程未发布时不能加入。

### 4. 课程内容

学生通过课程内容访问文件、试题和编程题。课程内容保存的是对资料库中内容的引用（`course_outline_item`），内容本身仍在各自的模块中。课程模块与内容模块之间通过 `shared/course` 下的接口对接，接口由内容模块实现，课程模块只依赖接口。

学生端访问一项内容时，要同时校验学习权和这项内容已编排进课程内容：

```java
// backend/server/src/main/java/cn/utcy/teaching/resource/application/CourseMaterialApplicationService.java
public DownloadTicket createDownload(long courseId, long materialId) {
    Actor actor = currentActor.require();
    courseAccess.requireLearningAccess(courseId, actor);
    if (!courseOutlineLinks.isLinked(courseId, CourseOutlineItemType.MATERIAL, materialId)) {
        throw new NotFoundException("课程内容中不存在该文件");
    }
    return ticket(requireMaterial(courseId, materialId));
}
```

### 5. AI 密钥按课程负责人取用

平台不持有大模型和 MinerU 的密钥。课程内的 AI 调用，无论由教师还是学生触发，都使用课程负责人的密钥，费用归开课教师，学生无需配置。负责人在「账户设置 → AI 服务」中填写。

各模块通过 `course/application/CourseAiKeys` 取用密钥：

```java
// backend/server/src/main/java/cn/utcy/teaching/course/application/CourseAiKeys.java
public String llmKeyForCourse(long courseId) {
    return configs.requireLlmKey(courseAccess.courseOwnerId(courseId), LLM_HINT);
}
```

MinerU 令牌由 `mineruTokenForCourse` 取用。负责人未配置时，请求返回提示「课程负责人尚未配置大模型 API Key……」。密钥的加密存储见 [大模型基础组件](01-大模型基础组件.md)。
