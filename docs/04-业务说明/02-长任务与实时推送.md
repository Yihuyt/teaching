# 长任务与实时推送

生成课件、解析教材、文档入库这类任务耗时较长，不能放在普通 HTTP 请求里同步等待结果。后端有两种运行方式，都通过 SSE（`text/event-stream`）向浏览器推送进度：

- 跟随连接：任务在一个流式请求中运行，连接断开即停止。用于智能课堂的生成与语音合成、试题生成、智能问答、积木编程助手。
- 后台运行：任务独立于连接，浏览器可以随时接入查看进度。用于知识库入库与重建索引、知识图谱教材构建。

代码在 `backend/server/src/main/java/cn/utcy/teaching/shared/sse/` 和 `shared/run/`，下文的类路径都相对于 `backend/server/src/main/java/cn/utcy/teaching/`。各接口推送的事件见 [前后端对接](../03-前后端对接.md)。

## 整体流程

```text
跟随连接
  浏览器 POST ──→ 应用服务（请求线程：鉴权、取密钥、校验参数）
                     ↓
                SseSupport.run：立即返回事件流，任务交给后台线程
                     ↓
                任务执行，逐步推送事件 ──→ 浏览器
                浏览器断开 → 取消标志置真 → 任务在下一个检查点停止

后台运行
  浏览器 POST 启动 ──→ 写入运行标记，打开进度通道，任务交给后台线程，立即返回
                     ↓
                任务执行：推送进度到 ProgressBus，定期写心跳
                     ↓
                结束：推送 done 或 error，关闭通道
  浏览器 GET 接入 ──→ ProgressBus.attach：先补发已有进度，再接收新事件
  判滞巡检 StaleRunCleaner：心跳长时间未更新的任务判为失败，教师可重试
```

## 主流程

### 跟随连接：SseSupport

应用服务在请求线程中完成鉴权、取密钥等检查，再调用 `SseSupport.run`。以智能课堂合成语音为例：

```java
// backend/server/src/main/java/cn/utcy/teaching/courseware/application/TtsApplicationService.java
public SseEmitter synthesizeSse(long courseId, long coursewareId) {
    courseAccess.requireManagementAccess(courseId, currentActor.require());
    String apiKey = aiKeys.llmKeyForCourse(courseId);
    return SseSupport.run(executor, objectMapper, sink -> {
        Summary summary = synthesize(apiKey, courseId, coursewareId,
                (done, total) -> sink.emit(Map.of("type", "progress", "done", done, "total", total)),
                sink::cancelled);
        sink.emit(Map.of("type", "done", "coursewareId", coursewareId, "version", summary.version(),
                "generated", summary.generated(), "skipped", summary.skipped()));
    });
}
```

检查放在 `SseSupport.run` 之前，出错时浏览器收到的是普通错误响应；进入 `run` 之后，错误以 `error` 事件推送。

`shared/sse/SseSupport.run` 创建事件流后立即返回，把任务交给后台线程执行。任务通过 `sink.emit` 推送事件；浏览器断开或超时后，`sink.cancelled()` 变为真。取消是协作式的：任务需要在检查点调用 `sink.cancelled()` 并自行停止，例如智能课堂逐页生成在每页开始前检查。

任务每完成一个单元就保存，例如逐页生成每完成一页即保存一页。中途断开时，已保存的部分保留。

### 后台运行：ProgressBus、RunFence、StaleRunCleaner

以知识库入库（`knowledgebase/application/DocumentIngestService`）为例，知识图谱教材构建（`knowledgegraph/application/KnowledgeGraphBuildPipeline`）采用相同的机制。

#### 1. 启动

启动接口把任务所在的行改为运行态，生成新的运行标记写入 `run_token` 列，打开一个进度通道，把任务交给后台线程，然后立即返回。

#### 2. 推送与接入进度

任务调用 `shared/sse/ProgressBus.publish(通道, 事件)` 推送进度，总线把事件存入该通道的内存快照，同时发给所有已接入的连接。浏览器通过 `GET .../events` 接入：任务运行中时，先补发快照中已有的事件，再接收新事件；任务不在运行时，返回一条按数据库状态生成的 `status` 事件后结束。关闭页面、刷新或断网都不影响任务本身。

#### 3. 写围栏与心跳

任务判为失败后可以重试，而旧线程可能仍在运行，它晚到的写入不能覆盖新一次运行的结果。因此每次写库都带上运行标记作为条件，心跳也是一条带标记的更新：

```java
// backend/server/src/main/java/cn/utcy/teaching/knowledgebase/infrastructure/KbDocumentMapper.java
@Update("""
        UPDATE knowledge_base_document SET progress_heartbeat_at = #{now}
        WHERE id = #{id} AND run_token = #{token}
        """)
int beat(@Param("id") long id, @Param("token") String token, @Param("now") LocalDateTime now);
```

`shared/run/RunFence.Heartbeat` 封装心跳写入。写入影响 0 行，说明运行标记已被替换，本次运行失效。任务在每个检查点同时判断取消和失效：

```java
// backend/server/src/main/java/cn/utcy/teaching/knowledgebase/application/DocumentIngestService.java
BooleanSupplier stop = () -> {
    heartbeat.beat();
    return task.cancelled.get() || heartbeat.lost();
};
```

#### 4. 判滞巡检

后端重启或线程卡死时，行会一直停在运行态，教师也无法重试。`shared/run/StaleRunCleaner` 负责把这些行判为失败：后端启动时，把所有处于运行态的行判为失败；运行期间定时巡检，把心跳长时间未更新的行判为失败。知识库和知识图谱各有一个子类（`StaleDocumentIngestCleaner`、`StaleGraphBuildCleaner`），教材构建判为失败后保留已完成的小节，可以从断点重试。

#### 5. 取消

后台任务不随连接断开而停止，由专门的取消接口处理。知识库入库在内存中设置取消标志；教材构建在数据库中记录取消请求，运行线程在写心跳时读取。
