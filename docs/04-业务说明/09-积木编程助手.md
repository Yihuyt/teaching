# 积木编程助手

积木编程让学生在课程里用嵌入的 Scratch 编辑器制作作品，旁边的 AI 助手有两种模式：讲解模式用文字和积木图讲解，修改模式直接修改编辑器中的作品，只对课程管理者开放。本文说明助手是怎样工作的。

代码分三部分：后端 `backend/server/src/main/java/cn/utcy/teaching/blockcoding/`，前端 `frontend/src/features/blockcoding/`，以及 `scratch-editor/`（官方 scratch-gui 的改制版）。智能体循环 `ChatAgentLoop` 见 [大模型基础组件](01-大模型基础组件.md)。

## 整体流程

```text
浏览器                                              后端
──────                                              ────
创作台页面
 ├ 编辑器 iframe（/scratch/teaching.html）
 │    ↑↓ postMessage 通信桥
 └ 对话面板
      发送消息（修改模式附带作品快照）  ──→  ChatTurn.send：搭建本轮工作台
                                              ↓
                                        ScratchProgramAgent（ChatAgentLoop）
                                          read_skill   读积木写法
                                          write_script 编译脚本，只改内存中的工作台
                                          final_answer 检查后回复
      ←── 流式推送回复 ───────────────────────┘
                                              ↓（修改模式）
      ←── browser_tool：建角色、插删脚本 ── ChangeCommitter 按改动清单逐项下发
      在编辑器中执行，回传结果 ─────────────→  继续下一项
      编辑器发生变化 → 自动保存作品
```

作品的实际状态只存在于浏览器的编辑器中。助手每轮从前端带来的快照读取作品，修改后再通过浏览器把改动写回编辑器，由编辑器的自动保存写回 OSS。

## 主流程

### 1. 编辑器嵌入与通信

创作台页面 `views/BlockCodingStudioView.vue` 用 iframe 嵌入 `/scratch/teaching.html`。`/scratch/` 由前端开发服务器或 nginx 转发到积木编辑器容器，与平台同源。`teaching.html` 是改制版新增的入口页，改制范围见 `scratch-editor/README.md`。

页面与编辑器之间用 postMessage 通信，协议在两边各定义一份：编辑器侧 `scratch-editor/src/lib/teaching-bridge/`，页面侧 `scratchBridge.ts`，修改时必须两边同时改。助手用到的主要请求是：

- `context/harvest`：取作品快照，包括各角色的造型、变量、列表、自定义积木和工作区里的积木；
- `blocks/insert`、`blocks/remove`：插入、删除积木段；
- `sprite/create`、`variable/create` 等：增删角色、变量和列表。

### 2. 发送消息

`ChatPanel.vue` 发送消息时，修改模式先取作品快照，一并发给 `ChatTurn.send`。后端为本轮搭建一个内存中的工作台 `Project`：

```java
// backend/server/src/main/java/cn/utcy/teaching/blockcoding/application/ChatTurn.java
Workspace workspace = project == null ? Workspace.CHAT : Workspace.PROJECT;
Project workbench = project == null
        ? Project.empty().inheritProcedures(agent.proceduresIn(prior.stream()
                .filter(m -> "assistant".equals(m.getRole())).map(BlockCodingChatMessage::getContent).toList()))
        : Project.fromHarvest(project, projectStacks.of(project));
```

- 修改模式：把快照中每个角色的积木拆成一段段脚本，转成文本记法并编号，登记进工作台。
- 讲解模式：不带作品，工作台为空，只继承此前回复中定义过的自定义积木。

### 3. 智能体运行一轮

两种模式的工具和系统提示词定义在 `Workspace` 中：

```java
// backend/server/src/main/java/cn/utcy/teaching/blockcoding/application/agent/Workspace.java
PROJECT(List.of(ScratchTools.READ_SKILL, ScratchTools.WRITE_SCRIPT, ScratchTools.LIST_PROJECT, ScratchTools.CREATE_SPRITE,
        ScratchTools.DELETE_SCRIPT, ScratchTools.DELETE_SPRITE, ScratchTools.DELETE_VARIABLE, ScratchTools.DELETE_LIST,
        ScratchTools.FINAL_ANSWER, ScratchTools.ASK_USER),
        "agent-system.md",
        "本轮到此为止,不能再写了。现在调用 final_answer 收尾:说明做了什么、怎么玩,没做完的如实说明;要问用户就调用 ask_user。"),

CHAT(List.of(ScratchTools.READ_SKILL, ScratchTools.FINAL_ANSWER),
        "chat-system.md",
        "本轮到此为止。现在调用 final_answer 把要告诉用户的话说完,没想清楚的如实说明。");
```

**提示词**（`ScratchAgentPrompt`）：系统提示词在 `resources/blockcoding/agent/` 下，写工具用法、积木记法和检查规则；用户消息依次是作品内容、学生拖入对话的积木、学生本次的话。课程的辅导提示词写进 `final_answer` 工具的说明，约束回复的写法。

**技能**：`resources/blockcoding/skills/<类别>/SKILL.md` 是各类积木（运动、外观、事件控制、变量列表等）的写法和示例。系统提示词里只列技能清单，模型调用 `read_skill` 时才读取正文。

**写脚本**：模型用 scratchblocks 文本记法写一段脚本，`ScratchTools.writeScript` 交给编译引擎：

```java
// backend/server/src/main/java/cn/utcy/teaching/blockcoding/application/agent/ScratchTools.java
Known known = project.knownFor(target.name(), true).withDeclaredLocals(localVariables, localLists);
Result result = engine.compile(body, known);
if (!result.ok()) {
    int times = project.failedAgain(target.name(), body);
    if (times >= STUCK_RESUBMITS) {
```

`Known` 是作品中已有的变量、列表和自定义积木，编译器据此判断名称是否正确。编译失败时，带行号的错误作为工具结果回给模型修改；编译通过的脚本只登记到工作台，编辑器此时不变。

**收尾**：回复通过 `final_answer` 提交，提交前有两道检查：回复中的每段积木图都用编译引擎检查写法；修改模式本轮有改动时，还要检查程序中的常见逻辑错误，例如使用了从未赋值的变量。检查不通过时打回给模型修改。

### 4. 改动写回编辑器

修改模式一轮结束后，`ChangeCommitter` 按工作台的改动清单依次落地：先建角色，再删旧脚本、插新脚本，再删变量和列表，最后删角色。每个动作都要在学生的浏览器中执行，由 `EditorBridge` 推送并等待结果：

```java
// backend/server/src/main/java/cn/utcy/teaching/blockcoding/application/EditorBridge.java
private JsonNode call(String name, Map<String, Object> args) {
    // 连接已断就没有人会执行:立刻报错,不空等超时
    if (sink.cancelled()) {
        throw new IllegalStateException("和编辑器的连接已断开");
    }
    String callId = calls.open();
    sink.emit(Map.of("type", "browser_tool", "callId", callId, "name", name, "args", args));
    return calls.await(callId);
}
```

前端在 `useEditorChanges.runBrowserTool` 中通过通信桥执行，再把结果回传给 `POST /api/v1/blockcoding/chat-sessions/{sessionId}/browser-tool-results`，唤醒后端等待的线程。全部完成后，助手消息连同改动清单一起保存；编辑器因积木变化触发自动保存。

### 5. 回退一轮改动

回退由前端在编辑器中完成（`useEditorChanges.revertChanges`）：按改动清单倒序，删除新写的脚本，插回被改写或删除的旧脚本，删除本轮新建的角色。完成后通知后端把这条消息标记为已回退，下一轮的历史会注明这些改动已被回退。

## 积木编译引擎

`blockcoding/engine` 负责文本记法与编辑器积木之间的转换：

| 类 | 作用 |
|---|---|
| `SbEngine` | 对外入口：`compile` 编译脚本，`check` 只检查写法 |
| `SbParser` | 把文本解析成语法树，直接运行 scratchblocks 官方的 JS 实现，与前端绘制积木图使用同一个库 |
| `ScriptCompiler` | 语法树 → 编辑器积木 XML，由通信桥插入工作区 |
| `BlockTable` | 积木表，来源是编辑器自身的积木定义（`editor-blocks.json`）和 scratchblocks 的拼写表（`commands.json`），编译通过即表示编辑器能识别 |
| `SbToText` | 反方向：编辑器积木 XML → 文本记法，用于读取作品快照 |
