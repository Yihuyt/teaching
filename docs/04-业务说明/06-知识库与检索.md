# 知识库与检索

知识库把课程资料变成可检索的段落：文档入库时被解析、切分、向量化后写入 Elasticsearch；检索时同时做关键词检索和向量检索，再融合两路结果。智能问答和试题生成通过同一个检索工具使用知识库。

代码在后端 `knowledgebase` 模块（建库、入库、检索）和 `retrieval` 模块（把检索包装成智能体工具），前端在 `frontend/src/features/knowledgebase/`。文档解析见 [大模型基础组件](01-大模型基础组件.md)，入库作为后台任务的运行机制见 [长任务与实时推送](02-长任务与实时推送.md)。

## 整体流程

```text
入库
资料库中的文件 ──→ DocumentParser 转成文字（PDF 经 MinerU）
               ──→ Chunker 切分成段落 ──→ 段落正文写入 MySQL
               ──→ 向量化 ──→ 写入 Elasticsearch（段落 id、章节、正文、向量）

检索
问题 ──→ 向量化 ──┬→ 关键词检索（BM25）─┐
                  └→ 向量检索（kNN）────┴→ 按名次融合 → 回 MySQL 取正文 → 交给模型
```

## 主流程

### 1. 发起入库

知识库的文档来自资料库：界面上的「上传文档」先把文件存入资料库，再按资料入库；也可以直接从课程资料中选择。两种入口都进入 `application/DocumentIngestService.ingest`，检查通过后插入一条待处理的文档记录，交给后台执行。

### 2. 解析和切分

后台由 `runDocumentPipeline` 依次执行：

1. `DocumentParser.parse` 把文件转成文字，PDF 经 MinerU 解析为 Markdown。
2. `domain/Chunker` 切分：按 Markdown 标题记录每段所属的章节路径，段内按句子组合到目标长度，相邻段落之间保留少量重叠。
3. 段落正文写入 MySQL 的 `knowledge_base_chunk`。正文以 MySQL 为准，Elasticsearch 中的数据可以随时由它重新生成。

### 3. 向量化，写入 Elasticsearch

`indexChunks` 分批调用 `LlmCalls.embed` 向量化，再批量写入 Elasticsearch。每个知识库对应一个物理索引，其中每段存段落 id、章节、正文和向量：章节和正文供关键词检索，向量供向量检索。全部写完后，文档标为就绪，可以被检索。

### 4. 检索

`application/KnowledgeBaseRetrievalService.retrieve` 是知识库对外提供的检索方法：

```java
// backend/server/src/main/java/cn/utcy/teaching/knowledgebase/application/KnowledgeBaseRetrievalService.java
float[] queryVector = llm.embed(apiKey, properties.embeddingModel(),
        properties.embeddingDimension(), List.of(query)).get(0);
int candidates = topK * 2;
List<String> bm25 = es.searchBm25(index, query, candidates);
List<String> knn = es.searchKnn(index, queryVector, candidates);
List<String> fused = RrfFusion.fuse(List.of(bm25, knn), topK);
```

- 关键词检索（BM25）擅长精确的术语，向量检索（kNN）擅长说法不同但意思相近的问题。
- 两路检索的分数无法直接比较，`RrfFusion` 按各段在两路结果中的名次融合排序（RRF）。
- 融合后按段落 id 回 MySQL 取正文和文档名，按顺序返回。

`retrieve` 不做访问控制，调用方需先校验课程权限和知识库挂载。

### 5. 包装成智能体工具

`retrieval/application/RetrievalTools` 定义检索工具 `rag`，智能问答和试题生成共用：

```java
// backend/server/src/main/java/cn/utcy/teaching/retrieval/application/RetrievalTools.java
return List.of(ToolSpecification.builder()
        .name("rag")
        .description("在挂载的某个知识库中检索相关段落。每个知识库调用一次,需要查多个知识库时按 kb_name 分别调用。")
        .parameters(JsonObjectSchema.builder()
                .addStringProperty("query", "非空自然语言查询;如果第一次检索效果不佳,换个查询角度")
                .addEnumProperty("kb_name", mounts.knowledgeBases().stream().map(KnowledgeBaseRef::name).toList(),
                        "要检索的知识库,必须是已挂载知识库之一")
                .required("query", "kb_name")
                .additionalProperties(false)
                .build())
        .build());
```

模型自己写查询词并选择知识库。每段检索结果在 `SourceRegistry` 中登记编号 `source-N`，以 `[source-N] 文档名 › 章节` 开头交给模型；回答中的引用和界面上的来源列表依靠这个编号对应。工具在智能体中的使用方式见 [智能问答](07-智能问答.md)。

## 重建索引

向量化使用的模型或维度改变后，旧向量与新问题的向量无法比较，知识库显示「需要重建索引」。`DocumentIngestService.rebuild` 读取 MySQL 中的全部段落重新向量化，写入一个新的物理索引，全部成功后才切换到新索引并删除旧索引。
