# 智能课堂

智能课堂是课程里可播放的多页课件。教师提供需求和素材，模型依次生成大纲、逐页内容和讲稿，最后合成语音。本文说明课件是怎样生成的。

后端在 `backend/server/src/main/java/cn/utcy/teaching/courseware/`，前端在 `frontend/src/features/courseware/`，提示词和输出格式在 `backend/server/src/main/resources/courseware/`。下文省略这些前缀。生成接口都是流式任务，机制见 [长任务与实时推送](02-长任务与实时推送.md)；`StructuredGenerator` 和提示词模板见 [大模型基础组件](01-大模型基础组件.md)。

## 整体流程

```text
上传素材 ──→ CoursewareMaterialBundleService ──MinerU / 直接读取──→ courseware_material_bundle
填写需求 ──→ StageGenerationService.outlineSse ──模型──→ 大纲（不保存，推给浏览器）
教师修改大纲并确认
        ──→ StageGenerationService.generateSse
              ├ 清空课件（resetInternal）
              ├ 各页并行：SceneGenerator.generateContent
              │     配图（文生图）→ 内容块 → 校验与排版检查 → 不合格回喂模型重写
              └ 按页序逐页保存（putSceneInternal）──→ courseware.body
生成讲稿 ──→ StageGenerationService.generateSpeechSse ──→ 逐页保存讲稿与动作
合成语音 ──→ TtsApplicationService ──语音合成──→ OSS courseware/{id}/audio/
```

## 课件的结构

整份课件是一个 JSON 文档，存在 `courseware` 表的 `body` 列，类型为 `domain/Stage.java`，与前端 `dsl/` 下的类型逐字段对应：

```text
Stage { title, theme, scenes[] }
 └ Scene { id, type, title, preset, summary, blocks[], speech[], layouts[], interactive, video }
     ├ blocks[]     内容块：heading、paragraph、bullets、formula、code、table、chart、
     │              emphasis、image、callout、columns、quiz_choice
     ├ speech[]     讲稿段 { text, actions[], audioPath }，动作为 highlight、reveal、pause
     ├ layouts[]    教师手工调整的位置和字号
     ├ interactive  交互页的网页 { html, widgetType, widgetOutline }
     └ video        视频页的视频 { src }
```

生成的页面有三类：讲解页（`content`）和测验页（`quiz`）由内容块组成，交互页（`interactive`）是一份自包含网页。视频页由教师上传，不参与生成。内容块只描述语义，位置和字号由排版引擎根据版式预设（`preset`）计算；讲稿动作按块 id 指向要高亮或揭示的内容块。

## 生成过程

### 1. 解析素材

`application/CoursewareMaterialBundleService.java`。PDF、Office 文档和图片用 MinerU 解析，txt、md 直接读取。`MaterialBundleBuilder` 把多份素材的文字按份分配字数后合并，并选出供模型参考的图片，结果存入 `courseware_material_bundle`。素材属于课件，不进资料库。

### 2. 出大纲

`StageGenerationService.outlineSse`，提示词 `prompts/templates/outline/`，输出格式 `schemas/outline.schema.json`。

大纲列出每一页的标题、类型、版式预设、要点，以及是否配图、用哪张素材图片。`refineOutline` 校验预设与页面类型匹配、交互页给出组件类型、页数和配比与教师的要求一致，不合格时回喂模型重写。

大纲不保存，以 `outline` 事件推给浏览器；教师在 `components/workbench/GenerationPanel.vue` 中修改，确认后整份发回后端。

### 3. 逐页生成

`StageGenerationService.generateSse` 接收确认后的大纲，先清空课件，再并行生成各页，按页序等待结果并逐页保存，每保存一页推送一次 `scene_done`。某一页失败时保存一页「本页生成失败，请重生成本页」的占位页，其他页继续生成。

每一页由 `SceneGenerator.generateContent` 生成：

1. 大纲为这一页要求了配图时，先调用文生图；素材图片则复制到本课件名下。
2. 讲解页和测验页用 `scene-blocks` 提示词生成内容块，最多 4 轮。
3. 每一轮由 `refineSceneBlocks` 检查：规范化块 id，校验业务规则（`domain/StageValidator`）和版式预设的结构要求（`checkPresetRules`），确认配图已放上页面，最后由排版引擎试排，超出版面时要求模型压缩文字。

```java
// backend/server/src/main/java/cn/utcy/teaching/courseware/application/SceneGenerator.java
Stage.Scene scene = new Stage.Scene(sceneId, brief.type(), brief.title(), brief.preset(), brief.summary(),
        normalized.value(), List.of(), List.of(), null);
String overflowMessage = layout.describeOverflow(scene);
List<String> warnings = new ArrayList<>(normalized.warnings());
if (overflowMessage != null && refineRound[0] < BLOCKS_MAX_ROUNDS) {
    overflowRounds[0]++;
    // 页内生成只能压缩不能拆页(拆页是教师的操作),所以只要求压缩,并且不许丢概要要求的知识点
    return StructuredGenerator.Refined.errors(List.of(overflowMessage
            + "请压缩文字:合并相近条目、缩短句子、去掉重复说明;概要要求的知识点一个都不能丢。"));
}
```

后端的排版引擎（`domain/layout/`）与浏览器中的排版引擎结果一致，后端判定放得下的页面在浏览器中同样放得下。

交互页由 `generateInteractiveHtml` 生成：按组件类型选择 `interactive-simulation`、`interactive-diagram`、`interactive-game`、`interactive-viz3d` 或 `interactive-html` 提示词，模型直接输出 HTML。`domain/InteractiveHtml` 校验它是完整的单个网页、不联网取数、外部资源只来自 jsdelivr、unpkg、cdnjs，不合格时回喂原因重写，最多 3 轮。

### 4. 生成讲稿与动作

`StageGenerationService.generateSpeechSse`，提示词 `prompts/templates/scene-speech/`。可以只补没有讲稿的页，也可以全部重写。

讲稿依据教师修改后的内容生成，动作引用内容块的 id，因此在内容定稿后再生成。各页并行生成，按页 id 保存。讲稿模型看到的测验题不含答案和讲解，避免讲稿提前说出答案。`refineSpeech` 去除指向不存在内容块的动作，超过一半的动作被去除时整份打回重写。

### 5. 单页重做

`StageGenerationService.regenerateSceneSse` 可以重做一页的内容，也可以只重写这一页的讲稿，并可附上调整要求。重做内容时，现有内容块作为基准交给模型；完成后这一页的讲稿和手工排版清空，因为它们引用的内容块可能已经不存在。

### 6. 合成语音

`application/TtsApplicationService.java` 找出所有没有音频的讲稿段，逐段调用语音合成并存到 OSS，全部完成后把音频地址合并回课件。合成期间文字被修改过的讲稿段不回填音频。
